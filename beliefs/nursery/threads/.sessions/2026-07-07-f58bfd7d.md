## The one hard gate: data retention

Claude Fable 5 (`claude-fable-5`) **requires 30-day data retention and is not available under zero data retention (ZDR)**. If your org (or workspace) is configured for ZDR — or any retention below 30 days — *every* Fable 5 request returns `400 invalid_request_error`, even with a perfectly valid payload.

So "authorizing usage" mostly means: make sure your org's retention config meets the 30-day minimum. That's set at the org level in the Console (Manage → your org's data-retention / privacy settings), or via your enterprise agreement. If you're on ZDR by contract, you'd need to change that arrangement with Anthropic.

## The rest is just normal API access

## If it's still failing — diagnose the 400

- **`400` on every request, valid body** → data-retention gate (the ZDR/30-day issue above). Fix the org retention config first.
- **`404`** → wrong model ID; use `claude-fable-5` exactly (no date suffix).
- **`403` permission error** → the API key's org/workspace doesn't have access to the model. Check the key's workspace in the Console.
- **`400` mentioning `thinking`/`temperature`** → not an access issue, an API-shape issue (Fable has always-on thinking; `temperature`/`top_p`/`top_k` and `budget_tokens` are rejected).
