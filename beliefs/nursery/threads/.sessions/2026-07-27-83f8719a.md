## Assistant

Yes to both, and the comparison is illuminating in both directions. Short version: Composable Beliefs and RDF/RDFS/OWL are solving the same problem family (machine-traversable, self-describing knowledge graphs with typed nodes and licensed inference), but they diverge sharply on where formal semantics lives, on change over time, and on who performs inference. The gap between them is exactly where the synergies are.

## Similarities

**Both are self-describing graphs.** The most striking parallel is reflexivity. RDFS is famously expressed in RDF itself (`rdfs:Class` is an instance of `rdfs:Class`), and OWL ontologies are exchanged as RDF documents (lecture, pp. 3, 8-9). Composable Beliefs does the same move: the schema's contracts are beliefs in the graph (cb:b051 defines the four structural types, cb:b053 the lifecycle, cb:b039/b043/b041 the closed enums), and `mix cb.verify.schema` checks the code against those in-graph contracts. `lib/cb/belief.ex:11-14` says it explicitly: "The DAG's own schema can be expressed as contracts in the DAG. Those contracts are the source of truth."

**Namespaced identifiers.** `cb:b051` is structurally a QName: a prefix declared by a collection manifest plus a local id, resolving to a globally unique node, exactly like RDF's `owl:Class` resolving against a namespace URI (p. 8). And a collection manifest's cross-namespace `depends_on` is a direct analog of `owl:imports` (p. 8): both declare that one knowledge module's meaning depends on loading another.

**Typed nodes with closed vocabularies.** The `type` field (attestation/aggregation/inference/prescription) plays the role `rdf:type` plays, and cb:b051's rule that "structural type determines which other fields are meaningful" is the same idea as OWL constraining which axioms apply to which entity categories. The `subjects` array, with its `{ref, type}` entries, is essentially a set of `rdf:type`-annotated resource references.

**Deterministic, rule-based derivation over the graph.** RDFS entailment and the OWL 2 RL profile derive new facts by applying rules directly over triples with polynomial-time algorithms (pp. 5-6). The belief shell is the same species of machine: `mix bs stale --cascade` computes a transitive closure over dep edges, pure and deterministic, no LLM. cb:b058 (subject containment: an aggregation's subjects must be a subset of the union of its deps' subjects) is precisely the kind of structural rule an RDFS/OWL-RL rule engine evaluates: a set-inclusion constraint checked mechanically over graph edges.

**Rejection of numeric confidence.** OWL is boolean, model-theoretic, with no fuzzy scores; Composable Beliefs expunged the `confidence` field for the same reason (`belief.ex:27-30` and `support/1`, which replaces it with deterministic structural counts). Both frameworks bet that dependency structure and evidence beat subjective scalars.

## Differences

**Where semantics lives.** This is the deepest one. In OWL, the claim itself is formal: `Man ≡ Human ⊓ Male` is a description-logic axiom with model-theoretic semantics, so a reasoner can decide entailment, and the whole OWL Full/DL/profiles hierarchy (pp. 4-6) exists to trade expressivity against decidability. In Composable Beliefs the `claim` is natural-language prose; only the *structure around it* (types, deps, status, enums, subject refs, contract rules) is formal. The machine checks structure; an LLM reads meaning. This sidesteps OWL's undecidability problem entirely (the formal fragment is trivially decidable, well below OWL 2 RL) at the cost of never being able to mechanically prove that two claims contradict each other. That's why the write flow needs `cb.preflight`/`cb.adjudicate`: conflict detection is semi-automated judgment, not entailment checking.

**Who performs inference.** OWL reasoners *compute* entailments; the conclusions are implicit in the axioms and materialized automatically. In Composable Beliefs, inference is an authored act: an inference node is minted by an agent, "licensed to exceed its deps," and pays for that licence by being independently falsifiable. The graph records reasoning; it does not perform it. OWL would treat an inference's conclusion as either entailed (hence redundant to state) or not entailed (hence unsound). CB deliberately occupies the middle ground OWL excludes: conclusions that go beyond what the premises formally entail, with the licence made inspectable.

**Open world vs closed world.** OWL assumes an open world (an unstated fact is unknown, not false) and no unique-name assumption (`SameIndividual`, p. 12, exists precisely because two names may denote one thing). CB verification is closed-world: a dep must resolve or the check fails (or explicitly skips, per cb:b058's third rule), enums are closed, and `cb.verify.collection` treats the loaded set as the universe. In this respect CB's contract-grade prescriptions are much closer to SHACL (the W3C's closed-world *validation* layer bolted onto RDF later, for exactly this reason) than to OWL.

**Change over time.** RDF/OWL have essentially no native story for revision; a triple is just asserted, and versioning/provenance require add-ons (named graphs, reification, PROV-O). CB makes temporality first-class: immutable nodes, supersession links, dated evidence entries as the one sanctioned in-place growth point, retraction with reasons. This is arguably CB's biggest structural contribution relative to the semantic-web stack.

**Prescriptions have no OWL analog.** OWL is purely descriptive: what is true of the domain. CB's fourth type, prescription (what should happen or must hold, with Gherkin-style rules and invariants as in cb:b051), is deontic. The closest semantic-web relatives are SHACL shapes and rule languages, not OWL itself.

## Synergies

- **The graph is one `@context` away from JSON-LD.** One JSON file per node, string ids, typed references: adding a JSON-LD context mapping (`deps` -> a dependency property, `superseded_by` -> a supersession property, `subjects` -> typed resource links, `type`/`kind`/`domain` -> class assertions) would make every belief a valid RDF resource with almost no change to the stored bytes. That would buy free interop with SPARQL endpoints, triple stores, and graph visualization tooling.
- **SKOS/OWL for the enums.** The closed kind/artifact-scheme/domain enums (b039/b043/b041) are exactly what SKOS concept schemes or small OWL class hierarchies are for, and `rdfs:subClassOf` would let kinds be organized hierarchically, which flat enums cannot express.
- **SHACL as a compile target for contract-grade prescriptions.** A prescription's `rules`/`invariants` (like b058's containment invariant) could be mechanically rendered as SHACL shapes, giving a second, independent verifier for the structural contracts.
- **PROV-O for evidence.** The `artifact` URI schemes plus dated evidence entries map cleanly onto PROV-O's entity/activity/agent model, which would formalize the provenance story for consumers outside the framework.
- **RL-style rules for the deterministic checks.** Checks like stale-cascade and subject containment are already shaped like OWL 2 RL rules operating "directly on RDF triples" (p. 6); expressing them that way would document them in a standard vocabulary, though the Elixir implementation is doing the same work today.

The clean summary: RDF/RDFS/OWL formalize *meaning* and leave provenance, revision, and judgment-bearing inference as afterthoughts; Composable Beliefs formalizes *provenance, revision, and the licence structure of reasoning* and leaves meaning in prose for an LLM to read. They are near-perfect complements, and an RDF export layer is the natural bridge if interop ever becomes worth the ceremony.
